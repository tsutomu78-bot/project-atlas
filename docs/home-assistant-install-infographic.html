Home Assistant OS · dedicated hardware

Put Home Assistant on a box that does nothing else.

A dedicated device running Home Assistant Operating System is the supported path: it ships the Supervisor, the add-on store and one-click backups, and it updates itself. Here is the whole install, from unboxing to your first automation, in seven steps.

Step 0 — the fork in the road

Pick the box. It decides whether you flash anything.

Everything after this is identical. The only difference between these three is who writes the operating system to storage — the factory, or you.

Raspberry Pi 5

The tinkerer's board: GPIO, fast USB, and an M.2 HAT for NVMe. Budget for the official 27 W supply — phone chargers brown out under load.

  • Image HAOS for RPi 5 (64-bit)
  • Storage 32 GB SD min.
  • Better NVMe or USB SSD
  • Power 5 V / 5 A USB-C
You flash it

x86-64 mini PC

An N100-class fanless box has headroom for cameras, voice and local LLM add-ons. Write the generic x86-64 image to the internal drive; it becomes an appliance.

  • Image HAOS generic-x86-64
  • Storage Internal SSD
  • BIOS Boot on AC restore
  • Note Wipes the disk

The install

Seven steps, in order

1

Lay out the parts

5 min

Gather these before you start, because discovering a missing item mid-flash costs you an evening: the device, its proper power supply, an Ethernet cable and a free router port, the storage medium, and a computer with a card reader or USB adapter.

Wired

Use Ethernet for the first boot even if you intend to run Wi-Fi later. Discovery, onboarding and the initial update all assume a stable link, and a hub that hosts your locks and heating deserves a cable.

2

Write Home Assistant OS to storage

10 min · skip on Green

Install Raspberry Pi Imager from raspberrypi.com — it carries the Home Assistant images directly, so there is nothing to download by hand. Then walk the menu:

Choose OS → Other specific-purpose OS → Home automation → Home Assistant → the image matching your board
  1. Pick the image for your exact hardware — an RPi 4 image will not boot an RPi 5.
  2. Insert the SD card or SSD and select it as the storage target. Its contents are overwritten.
  3. Choose Next → Write, wait for the verify pass, then Finish and eject.
Gotcha

Decline Imager's OS customisation prompt — hostname, SSH keys and user accounts. Those settings are written for Raspberry Pi OS and are ignored here; Home Assistant OS has no shell user to configure and creates its own admin account in step 5.

3

Cable it up, then apply power

2 min

Storage in, Ethernet into the router, power last. The hub, the router and the laptop you will onboard from must all sit on the same network segment — guest VLANs and Wi-Fi isolation break the .local name lookup you are about to use.

4

Leave it alone for twenty minutes

~20 min, unattended

The first boot is not idle. Home Assistant OS partitions the disk, pulls its container images and starts the Supervisor. Pulling power in the middle of this is the single most common way to end up re-flashing. Go and make coffee.

5

Open the hub in a browser

1 min
http://homeassistant.local:8123

A “Preparing Home Assistant” screen means it is still working — wait, don't reload repeatedly. If the name does not resolve at all, walk down this ladder: homeassistant:8123, then the IP address the router handed out, from its DHCP client list.

6

Onboard: account, home, location

5 min

Five browser screens, no config files. Everything here is editable later except the username on the owner account.

  1. Create the owner account. This is the administrator; give it a real password, not a placeholder you plan to change.
  2. Name your home and drop its pin on the map.
  3. Set location details — time zone, elevation, unit system. Sunrise and sunset triggers, weather and presence all read from these, so a lazy pin makes bad automations later.
  4. Choose your analytics setting. Opt in or out; it is genuinely optional.
  5. Review discovered devices. Anything already broadcasting on your network shows up here — add the ones you recognise, leave the rest.
7

Pin the address and turn on backups

5 min

Do these two before you build anything, while there is still nothing to lose.

  1. In your router, reserve a fixed DHCP lease for the hub's MAC address. Every integration you add will point at this address.
  2. Settings → System → Backups: switch on the automatic schedule and send copies somewhere off the device — a network share or Home Assistant Cloud. A restore is a single file.
  3. Settings → System → Updates: apply anything pending, then reboot once so you start from a clean, current install.
Remote

Do not port-forward 8123 to the internet. Reach the hub from outside with Home Assistant Cloud or a VPN back into your own network — the hub speaks to your locks, cameras and heating, and its login page is not something to leave on a public port.

When it doesn't come up

Four failures cover almost everything

What you seeUsually meansDo this
Name never resolves mDNS is blocked or the client is on a guest / isolated network Try homeassistant:8123, then the raw IP from the router's DHCP list
No lights, no link LED Under-powered supply, or a charger negotiating the wrong profile Use the official PSU for the board — 5 V / 5 A USB-C on a Pi 5
Rainbow screen or boot loop Wrong image for the board, or a bad write to the card Re-flash with the image named for your exact model; replace suspect SD cards
Works, then dies weeks later SD card wear — the classic Pi failure mode Move to an SSD or NVMe and restore from a backup
