Step 0 — the machine

What you already have, and what to check before you start

Why the X260 is a good hub

Three things matter in a hub, and this laptop has all of them. Gigabit Ethernet on board, so no Wi-Fi dropouts between your automations and your lights. A dual battery — Lenovo's Power Bridge pairs an internal cell with a hot-swappable external one — which rides out short power cuts without you buying a UPS. And x86-64 with real headroom: cameras, voice pipelines and local add-ons that choke a Raspberry Pi run comfortably here.

CPU
6th-gen Intel Core U-series — ample for Home Assistant
RAM
One SODIMM slot, 16 GB max. 8 GB is plenty; 4 GB is tight if you want add-ons
Disk
2.5-inch SATA bay. This is the drive you will flash — an SSD, ideally 120 GB or more
Network
Gigabit Ethernet — use it, not Wi-Fi
Radios
None usable for Zigbee or Thread. Budget a USB stick if you want them

Check these before you commit

  • 01Back up anything still on the diskThe flash overwrites the whole drive. There is no partition step and no undo.
  • 02Inspect the external batteryIf it is swollen or the case no longer sits flat, take it out and bin it responsibly. Run on mains only.
  • 03Confirm it holds charge at allA dead battery is fine — it just means no UPS. A degraded one that reboots under load is not.
  • 04Blow out the fanThis box will now run 24/7. Five minutes with compressed air buys you years.
  • 05Decide where it livesNext to the router, lid open, hard surface, not in a cupboard.

One decision, before you flash

Give the whole laptop to Home Assistant, or virtualise it?

The rest of this guide assumes the first. The second is worth ten minutes' thought only if you already know you want the machine doing more than one job.

Recommended

Home Assistant OS, bare metal

Write Home Assistant OS straight onto the SATA drive. The laptop becomes an appliance: it boots into Home Assistant, updates itself, and has no login shell to maintain. Supervisor, the add-on store and one-click backups all come included.

Pick this if the laptop has no other job. Simplest to install, simplest to live with.

More work

Proxmox, with Home Assistant OS in a VM

Install a hypervisor first, then run Home Assistant OS as one virtual machine beside others. You gain whole-system snapshots before every risky change, and room for a network-wide ad blocker or a media server on the same box.

Pick this if you want snapshots or a second service, and don't mind maintaining a hypervisor.

The install

Seven steps, in order

1

Set up the BIOS first

10 min

Do this before flashing — a machine that will not boot the new drive is much harder to diagnose afterwards. Power on and tap F1 (or Enter, then F1) to reach ThinkPad Setup.

  • Security → Secure Boot → Disabled. Non-negotiable: Home Assistant OS is not signed for Secure Boot and simply will not start with it on.
  • Startup → UEFI/Legacy Boot → UEFI Only. The generic x86-64 image is built to boot UEFI.
  • Boot order: put the internal drive first once you're done, and USB first while you're installing.
  • Config → Power: enable Wake on LAN if it's offered — useful later, harmless now.
  • Note the drive's own settings: if the disk has a BIOS password or hardware encryption set from a previous life, clear it now.
2

Write Home Assistant OS to the internal drive

20 min

This is the one place a laptop differs from a mini PC: you cannot write an operating system onto the disk a machine is currently running from. Pick whichever route matches the tools on your bench. You want the file named:

haos_generic-x86-64-<version>.img.xz

Route A — pull the drive Easiest, if you own a USB-SATA adapter

  1. Power off, unplug, remove the external battery, and disable the internal battery in Config → Power first.
  2. Undo the bottom cover and lift out the 2.5-inch drive in its caddy.
  3. Connect it to another computer with a USB-SATA adapter or dock.
  4. Write the image with Balena Etcher or Raspberry Pi Imager's Use custom option — both read .img.xz directly, no unpacking.
  5. Put the drive back in the laptop.

Route B — flash it in place No disassembly, one command

  1. Write a normal Ubuntu desktop image to a USB stick on any computer.
  2. Boot the X260 from that stick and choose Try Ubuntu — a live session, nothing installed.
  3. Identify the internal disk with lsblk. It is the one whose size matches the laptop's drive, typically /dev/sda.
  4. Decompress and write in one pass, replacing the device name with the one you just confirmed.
  5. Shut down, remove the stick, boot from the internal drive.
Check twice

Route B writes to a raw device with no confirmation prompt. Read the output of lsblk carefully and make sure the target is the internal disk, not the USB stick you booted from — the command will happily destroy either.

3

Cable it up, then power on

2 min

Ethernet into the router, charger in, lid open for now. The hub, the router and the laptop or phone you will onboard from all need to sit on the same network segment — guest networks and Wi-Fi client isolation break the .local lookup you are about to use.

4

Leave it alone for twenty minutes

~20 min, unattended

The first boot is not idle. Home Assistant OS expands its partitions, pulls its container images and starts the Supervisor. The screen will sit on a console log that looks stuck — it isn't. Pulling the power here is the most common way to end up re-flashing.

5

Open the hub from another device

1 min
http://homeassistant.local:8123

A “Preparing Home Assistant” screen means it is still working — wait rather than reloading. If the name doesn't resolve, walk down the ladder: homeassistant:8123, then the IP address your router handed out, from its DHCP client list.

6

Onboard: account, home, location

5 min

Five browser screens, no config files. Everything is editable later except the username on the owner account.

  1. Create the owner account. This is the administrator — give it a real password, not a placeholder you plan to change.
  2. Name your home and drop its pin on the map.
  3. Set location details — time zone, elevation, unit system. Sunrise and sunset triggers, weather and presence all read from these, so a lazy pin makes bad automations later.
  4. Choose your analytics setting. Opt in or out; it is genuinely optional.
  5. Review discovered devices. Anything already broadcasting on your network appears here — add what you recognise, leave the rest.
7

Settle it in: address, lid, backups

10 min

Three things to do while there is still nothing to lose.

  1. Reserve its address. In your router, give the X260's MAC a fixed DHCP lease. Every integration you add will point at it.
  2. Turn on backups. Settings → System → Backups: enable the automatic schedule and send copies off the device — a network share or Home Assistant Cloud. A restore is a single file.
  3. Update, then reboot once from Settings → System → Updates, so you start current and clean.
The lid

Home Assistant OS can suspend when the lid closes, which takes your whole smart home down with it. The reliable answer is to leave the lid open. If you must close it, log in as root at the physical console and set HandleLidSwitch=ignore in /etc/systemd/logind.conf — but treat that as unproven on your machine: test it for an hour, and re-check after every OS update, because the system partition is managed by the OS.

Remote

Do not port-forward 8123 to the internet. Reach the hub from outside with Home Assistant Cloud or a VPN back into your own network — this box now speaks to your locks, cameras and heating, and its login page is not something to leave on a public port.

When it doesn't come up

Five failures cover almost everything

What you seeUsually meansDo this
Lenovo logo, then nothing Secure Boot still enabled, or the machine is in Legacy boot mode Back into ThinkPad Setup: Secure Boot off, UEFI Only, internal drive first in the boot order
Name never resolves mDNS is blocked, or your phone is on a guest / isolated network Try homeassistant:8123, then the raw IP from the router's DHCP list
Everything dies when you shut the lid Suspend on lid close Run it lid-open, or apply the logind.conf change and re-test after each update
Reboots at random under load A tired battery or a failing charger, not software Remove the external battery and run on mains; swap the charger before you suspect Home Assistant
Fine for weeks, then slow A dying SATA disk — likely the original one from this laptop's first life Fit a known-good SSD and restore from a backup
