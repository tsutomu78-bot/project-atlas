Home Assistant OS · HP 255 G4

Yes, your old laptop is the dedicated device.

No Raspberry Pi, no Docker, no second machine to keep running. You wipe Windows off the HP 255 G4 and install Home Assistant Operating System in its place — the laptop stops being a laptop and becomes an appliance that boots straight into your smart home.

First, what this actually is

Three things it isn't

Flashing firmware

It's an operating system

You are not touching the BIOS chip. You write Home Assistant OS onto the hard drive, exactly where Windows lives now. Windows and every file on that disk are gone.

You need Docker

It's already inside

Home Assistant OS ships the container engine, the Supervisor and the add-on store built in. You never type a Docker command, and it updates itself from the web interface.

You need a Raspberry Pi

A laptop is the same thing

There is an official image for ordinary PCs. A laptop is simply a PC with a screen and a battery attached — and the battery is a bonus, not a problem.

Step 0 — the machine

The 255 G4 will do this. Here's what it will and won't run.

Honest verdict: good enough, with a ceiling

The 255 G4 is a 2015 budget machine — an AMD E1 or A6 chip, up to 8 GB of RAM, and 100 Mbit Ethernet rather than gigabit. None of that blocks Home Assistant, whose normal traffic is tiny. It does set a ceiling: this is a hub for lights, plugs, sensors, heating, presence and dashboards, comfortably. It is not the box for continuous camera recording or local voice assistants — those want far more CPU than a 15 W 2015 APU has.

CPU
AMD E1-6015 (dual-core) or A6-6310 / A8-7410 (quad-core). All 64-bit — the image will run
RAM
Two slots, 8 GB maximum. 4 GB works; 8 GB gives room for add-ons
Disk
2.5-inch SATA. Most shipped with a 5400 rpm hard disk — see the bench list below
Network
Realtek 10/100 Ethernet. Fine for this job; use it, not Wi-Fi
Radios
Nothing usable for Zigbee or Thread. That's a USB stick, later

Check these before you start

  • 01Copy off every file you care aboutPhotos, documents, browser passwords. The install erases the whole disk with no undo and no partition step.
  • 02Note your Windows licence is goingIt stays tied to the hardware, but you're not coming back mid-week — decide now.
  • 03Check the batteryIf it's swollen, remove it and run on mains. A healthy one gives you a free mini-UPS; a dead one costs you nothing.
  • 04Blow out the fan ventThis machine is about to run 24/7 for years. Five minutes with compressed air is the cheapest insurance here.
  • 05Pick its spotNext to the router, lid open, hard surface, not shut in a cupboard.

On the bench

What to have ready before step 1

Required

A USB stick, 8 GB minimum

16 GB is more comfortable — the Ubuntu download is around 6 GB. It becomes a temporary boot stick: the tool you use to write Home Assistant OS onto the laptop's own drive. Its contents get erased; you get the stick back afterwards.

Required

A second working computer

Any Windows, Mac or Linux machine, just to make that USB stick. Plus an Ethernet cable and a free port on your router.

Recommended

A 2.5-inch SATA SSD

120–240 GB is ample. Ten-year-old spinning disks are the most likely thing to fail in this build, and swapping it now means you install once. Skip it if the machine already has an SSD.

The install

Seven steps, in order

1

Rescue your files, then let the disk go

Varies

Boot the HP into Windows one last time and copy anything you want off it — to a second USB stick, an external drive, or cloud storage. From step 5 onwards that disk is overwritten in a single pass. There is no “keep my files” option in this process, because Home Assistant OS is not a Windows-style installer at all.

2

Set the BIOS up correctly

10 min

Do this before writing anything. Power on and tap F10 repeatedly to enter HP Computer Setup — Esc first gives you the menu if F10 doesn't catch it.

  • Security → Secure Boot Configuration → Secure Boot: Disable. Home Assistant OS is not signed for Secure Boot and will not start with it on.
  • Legacy Support: Disable. You want UEFI booting — that's what the image expects.
  • Boot order: USB first for now. You'll put the internal drive back on top once it's installed.
  • Press F10 to save. HP will show a four-digit code and ask you to type it and press Enter — that's normal, and it's confirming the Secure Boot change.
Fitting an SSD

If you bought one, now is the moment: power off, unplug, remove the battery, and swap the 2.5-inch drive before you go any further. There's nothing to clone — the new disk gets written from scratch in step 5.

3

Make the Ubuntu boot stick

15 min

On your other computer. Ubuntu here is only a temporary toolbox — you are not installing it, just borrowing a working Linux long enough to write to the HP's disk.

  1. Download Ubuntu Desktop from ubuntu.com/download/desktop — take the LTS version it offers. It arrives as one large .iso file, around 6 GB. Save it to your Downloads folder — right-click the link and choose Save link as… — and let it finish completely. Never click “Open” on the finished download.
  2. Get the writing tool. On Windows, Rufus from rufus.ie — one small .exe, nothing to install. On Mac or Linux, Balena Etcher from etcher.balena.io.
  3. Plug in the stick — and move anything you care about off it first.
  4. In Rufus: Device → your USB stick → SELECT → the Ubuntu .iso → START. Take the default Write in ISO Image mode if it asks, then accept the warning that the stick will be erased. (In Etcher, it's Flash from file → Select target → Flash.) Either way, check the target size matches your stick.
  5. Let it finish. Don't unplug while it writes or verifies — Rufus says READY when it's done.
The popup

When it finishes, Windows will probably say “You need to format the disk before you can use it”. Click Cancel. Nothing has gone wrong — Windows simply can't read the Linux layout Etcher just wrote. The stick is ready to boot.

Why Rufus

Etcher on Windows commonly fails with Error opening source … (0 , h.requestMetadata) is not a function. That is a known, still-open Etcher bug across several versions — not a problem with your download, your path, or your permissions, and running it as administrator doesn't help. Don't spend an evening on it; Rufus writes the same stick in two minutes.

Don't open the ISO

Double-clicking the downloaded file mounts it as a virtual DVD drive, which locks it — moving it afterwards fails with “the file is open in System”. In This PC, right-click the Ubuntu DVD drive that appeared and choose Eject. Copying instead of moving usually works too.

4

Boot the HP from the stick

5 min

Plug the stick into the HP, connect the Ethernet cable to your router, and power on tapping F9 for the boot menu. Choose the USB device, then choose Try Ubuntu — not Install Ubuntu. You'll land on a normal desktop running entirely from the stick, with the internal disk untouched.

Confirm you have internet: open Firefox and load any page. You need it for the next step.

5

Write Home Assistant OS onto the internal disk

15 min

In the live Ubuntu session, open Firefox and go to the Home Assistant OS releases page on GitHub. Under the newest release, find the file for generic PCs — its name looks like haos_generic-x86-64-<version>.img.xz — and right-click to copy its download link.

Then open Terminal and run these, one line at a time:

# 1. list the disks — find the internal one by its size $ lsblk # 2. download the image (paste the link you copied) $ wget <paste-the-link-here> # 3. write it — replace sda if lsblk showed a different name $ xzcat haos_generic-x86-64-*.img.xz \ | sudo dd of=/dev/sda bs=4M status=progress conv=fsync # 4. flush everything to disk before powering off $ sync
Read this twice

In lsblk, the internal disk is the one whose size matches the laptop's drive — 500 GB, 240 GB, whatever you fitted. Your USB stick is the small one, and it is probably sdb. Point dd at the wrong name and it will erase the stick instead, silently and without asking.

When it finishes, shut down, pull out the USB stick, and put the internal drive first in the boot order (F10 again). Power on.

6

Leave it alone for twenty minutes

~20 min, unattended

The first boot is not idle. Home Assistant OS expands its partitions, pulls its components and starts the Supervisor. The screen will sit on scrolling text or a near-blank console — that is what a working install looks like. Do not pull the power; that's the most common way to end up starting over.

7

Open it in a browser and onboard

10 min
http://homeassistant.local:8123

From your phone or the other computer. “Preparing Home Assistant” means it's still working — wait rather than reloading. If the name doesn't resolve, try homeassistant:8123, then the IP address from your router's device list.

Then five screens, no config files and no command line:

  1. Create the owner account — the administrator. Give it a real password.
  2. Name your home and drop its pin on the map.
  3. Set time zone, elevation and units. Sunset triggers and weather read from these, so a lazy pin makes bad automations later.
  4. Choose your analytics setting — genuinely optional.
  5. Review discovered devices — whatever is already on your network shows up here.

Finally, three things worth doing straight away:

  1. Reserve its address in your router, as a fixed DHCP lease against the HP's MAC.
  2. Turn on backups in Settings → System → Backups, with copies stored off the device.
  3. Apply updates in Settings → System → Updates, then reboot once.
The lid

Home Assistant OS may suspend when you close the lid, taking the whole smart home down with it. The dependable answer is to leave the lid open. There is a logind.conf change people apply from the console, but reports are mixed and the system partition is managed by the OS — so treat it as unproven, test it, and re-check after updates.

Remote access

Do not port-forward 8123 to the internet. Use Home Assistant Cloud or a VPN into your own network. This box now speaks to your locks, cameras and heating; its login page does not belong on a public port.

Once it's running

Your five device types, and what each one needs

Every brand is its own integration in Home Assistant — you add them one at a time from Settings → Devices & services, and mixing brands is normal, not a problem. What differs is whether a brand talks to the hub directly or bounces through its own cloud.

What you're addingHow it connectsWatch out for
Lights One integration per brand. The easiest wins on this list Check each brand's integration page for “local push” — that's the ones that keep working when your internet is down
Camera A camera entity you can view on a dashboard Viewing is fine; continuous recording is not on this CPU. Leave recording to the vendor app or an SD card. Cameras offering a local RTSP stream behave far better here
Doorbell A button-press event, plus a camera entity The event is the valuable part — it triggers announcements and lights. Expect a lag on live video; don't judge the build by it
Blinds Cover entities, with open / close / position Position control depends on the brand exposing it. Some only offer open and close, and no integration can invent the rest
Thermostat A climate entity with target temperature and modes The most cloud-locked category. Some makers require you to register for developer API access before Home Assistant can talk to them at all
No Zigbee

A fair call when you're buying across brands — but know the trade. Wi-Fi devices mostly route through their maker's cloud, so an internet outage can take your automations with it, and a discontinued app can strand a device. The escape hatch that needs no USB stick is Matter over Wi-Fi: devices carrying that badge are controlled locally by the hub. Worth checking for on the next thing you buy, rather than replacing anything you already have.
